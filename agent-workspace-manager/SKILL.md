# Agent Workspace Manager

Isolated development workspace manager using Git Worktree. Workspaces are created
as **sibling directories** of the source project, keeping the main working tree
clean while allowing parallel work on different branches.

## Installation

Run once after installing the skill:

```bash
bash install.sh
```

This installs `ws`, `wscreate`, `wslist`, `wsopen`, `wsdelete` to `~/.local/bin/`.

## Commands

```
ws create [branch-name]              Create a workspace (default: master)
ws list [--project PROJECT]          List all managed workspaces
ws open --name NAME [--project P]    Open a workspace in IDEA
ws delete --name NAME [--project P]  Delete a workspace (branch preserved)
```

Alias form (direct dispatch, no subcommand needed):

```
wscreate [branch-name]
wslist [--project PROJECT]
wsopen --name NAME [--project P]
wsdelete --name NAME [--project P]
```

## Quick Start

```bash
# In your project directory:
wscreate                    # create workspace on master (auto-suffix if master is current)
wscreate feature-login      # create workspace on feature-login branch
wslist                      # list all workspaces
wsopen --name feature-login # open in IDEA
wsdelete --name feature-login  # delete workspace (branch preserved)
```

## How It Works

### Workspace Creation (`ws create`)

1. Detects the git repo root from the current working directory
2. Determines the workspace path: `{project_parent}/{project_name}-{branch_name}/`
3. If the branch exists -> checks it out in the new worktree
4. If the branch doesn't exist -> creates it from current HEAD
5. If the branch is the current branch -> creates a new branch with suffix (-2, -3)
6. Copies IntelliJ IDEA configuration using **blacklist strategy** (see below)
7. Registers the workspace in `~/.workspace-manager/registry.json`
8. **Attempts to launch IDEA immediately** -- if the executable is not found,
   shows an error with the config file path and common IDEA locations. The
   workspace is still created successfully (exit 0); user can run `wsopen`
   after setting `ideaExecutable` in `config/config.json`.

### IDEA Configuration Copying

**Strategy: blacklist.** Copies everything in `.idea/` and root-level `*.iml`
files, EXCEPT runtime state files that cause path conflicts or stale data.

Copied (key items):
- `modules.xml` — module definitions (links .iml files)
- `*.iml` — module SDK, dependencies, output paths
- `compiler.xml` — compiler settings
- `misc.xml` — project SDK, language level
- `vcs.xml` — VCS mappings
- `encodings.xml` — file encodings
- `codeStyles/` — code style settings
- `runConfigurations/` — run/debug configurations
- `inspectionProfiles/` — inspection profiles
- `libraries/` — library references (Maven deps, etc.)

Blacklisted (never bulk-copied, removed if git checked them out):
- `workspace.xml` - **partially extracted** (see below), not bulk-copied
- `tasks.xml` - task list (change-specific)
- `usage.local.xml` - usage statistics
- `shelf/` - shelved changes
- `caches/` - index caches (regenerated by IDEA)
- `local_history/` - local history (path-specific)

### workspace.xml Component Extraction

`workspace.xml` is a **mixed file**: it contains both useful project
configuration AND runtime UI state. It is NOT bulk-copied, but useful
components are **extracted** from it and written to the destination.

Extracted (copied to destination workspace.xml):
- `MavenProjectsManager` - Maven project tree: linked pom.xml files, resolved
  dependency list, ignored pom files. Without this, Maven projects must be re-linked.
- `MavenImportPreferences` - Maven workspace settings: Maven home path,
  settings.xml path, import options (auto-download sources/docs), profile
  selections. This is the actual "Maven configuration" users care about.
  Without it, Maven settings reset to defaults in the new workspace.
- `RunManager` - run/debug configurations NOT saved as separate project files
  (i.e., user didn't check "Store as project file"). Shared run configs in
  `.idea/runConfigurations/*.xml` are already copied by the blacklist strategy.

Discarded (UI state, regenerated by IDEA on open):
- `FileEditorManager`, `ToolWindowManager`, `DebuggerManager`,
  `RecentProjectsManager`, `UsageViewManager`, etc.

The keep list is `WORKSPACE_XML_KEEP_COMPONENTS` in `scripts/lib/config.py`.
Components use `$PROJECT_DIR$` macro for project paths, which resolves
automatically to the new workspace path - no manual path fixing needed.

**Important**: The component name for Maven settings is `MavenImportPreferences`,
NOT `MavenProjectsManager`. `MavenProjectsManager` only stores the project tree
(linked pom files). The actual Maven configuration (Maven home, settings.xml
path, import options) is stored under `MavenImportPreferences` -- this was
confirmed from IntelliJ Community source code:
`@State(name = "MavenImportPreferences", storages = @Storage(StoragePathMacros.WORKSPACE_FILE))`
in `MavenWorkspaceSettingsComponent.java`.

**Maven home caveat**: The deprecated `mavenHome` field in workspace.xml is
always saved as "Bundled Maven 3" by IDEA (intentionally, via a
`myForPersistence` flag in `MavenGeneralSettings.java`). The actual custom
Maven path, if configured, is stored in `customMavenHome` and
`mavenHomeTypeForPersistence` fields within the same `MavenImportPreferences`
component. Our extraction copies the entire component, so these fields come
over. If the user reports Maven home not carrying over, check whether the
SOURCE workspace.xml has `customMavenHome` at all -- Bundled/Wrapper users
won't have it. See Pitfall 14 in the pitfalls reference for full details.

XML parsing is namespace-safe: if IDEA adds an `xmlns` attribute to the
`<project>` root element, the extraction code strips namespace prefixes
from tag names before matching component names.

### Workspace Path

Workspaces are always created as **siblings** of the project directory:

```
/home/user/projects/
├── my-project/                    ← source project (main worktree)
├── my-project-master/             ← workspace for master branch
├── my-project-feature-login/      ← workspace for feature-login branch
└── my-project-hotfix-1/           ← workspace for hotfix-1 branch
```

### Delete (`ws delete`)

Deletes the worktree directory and removes the registry entry. The git branch
is **preserved** — users decide whether to delete branches manually.

Force removal is always used because the skill intentionally writes untracked
IDEA config files into the workspace (see pitfalls reference).

### Registry

All workspace metadata is stored in `~/.workspace-manager/registry.json` with
atomic writes (temp file + rename) and file locking (fcntl on Linux, fallback
on Windows).

### Rollback

If any step in `create` fails, all completed steps are rolled back in reverse
order: registry entry -> IDEA config files -> git worktree.

NOTE: If the IDEA launch fails (executable not found), the workspace is NOT
rolled back -- it was already created successfully. The user sees a WARNING
with the config file path and common IDEA locations, and can run `wsopen`
after setting `ideaExecutable` in `config/config.json`.

## Configuration

Config file: `config/config.json` (relative to skill directory)

| Key | Default | Description |
|-----|---------|-------------|
| ideaExecutable | null | Path to IDEA executable (null = auto-detect) |
| copyIdeaConfiguration | true | Copy .idea/ config and .iml files |
| enableLogging | true | Write JSON-lines logs |
| enableRollback | true | Auto-rollback on failure |

## Data Locations

```
~/.workspace-manager/
├── registry.json          Workspace registry
├── registry.json.bak     Backup of last write
└── logs/
    └── workspace-YYYY-MM-DD.jsonl   Structured logs
```

## v3.2 Changelog

- **MavenImportPreferences added**: Root cause of Maven config not carrying over
  was a wrong component name. `MavenProjectsManager` only stores the project
  tree (linked pom files). The actual Maven configuration (Maven home path,
  settings.xml path, import options, profile selections) is stored under
  `MavenImportPreferences` -- confirmed from IntelliJ Community source:
  `@State(name = "MavenImportPreferences")` in `MavenWorkspaceSettingsComponent.java`.
- **Namespace-safe XML parsing**: workspace.xml with `xmlns` attribute on root
  element no longer breaks component extraction. All `findall('component')`
  replaced with namespace-stripping iteration.
- **Auto-launch on create**: `wscreate` now passes `launch_idea=True` to
  `manager.create()`, so IDEA is attempted immediately after workspace creation.
  Previously create did not try to launch, so the user/agent wouldn't discover
  a missing IDEA executable until they manually ran `wsopen`.

## v3.1 Changelog

- **workspace.xml component extraction**: `MavenProjectsManager` and `RunManager` are now
  extracted from the source `workspace.xml` and written to the destination. Previously the
  entire `workspace.xml` was blacklisted, causing Maven settings and non-shared run configs
  to be lost on workspace copy. UI state (FileEditorManager, ToolWindowManager, etc.) is
  still discarded. The keep list is `WORKSPACE_XML_KEEP_COMPONENTS` in `scripts/lib/config.py`.
- **IDEA launch error handling**: `launch()` now raises `IdeaError` instead of silently
  returning `None`. `wsopen` failure shows the config file path and common IDEA locations.
  `wscreate` still succeeds (exit 0) if IDEA can't launch -- the workspace is usable.

## Platform Support

Cross-platform Python 3 (tested on Linux). Windows and macOS supported for:
- Git worktree operations
- IDEA executable detection
- File locking (fcntl on Linux, atomic lock file on Windows)
